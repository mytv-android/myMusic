切歌不再硬切

现在一首播完，下一首从第一个采样直接开始。参考 Folia 的智能过渡（Automix），给切歌加两档：固定时长的交叉淡化，和先把两首歌分析一遍再决定怎么接的自动混音。 能提前拿到整首音频的用完全体，拿不到的就退回淡化，设置页写明这次为什么退回。

参考：folia-site.cielaniska.top/guide/automix 现状：0 处过渡 分析复用现有节拍跟踪 不引入新模型
00

结论

参考文档把过渡分成两档：永远可用的固定淡化，和依赖分析的 Automix。我们照这个分法做，但把「完全体 / 兼容模式」换成手机端更实际的条件——能不能在切歌前拿到下一首的完整音频。

2档过渡交叉淡化 · 智能过渡
4种接法切拍 / 低频交接 / 尾奏承接 / 等功率淡化
0个新模型节拍复用 RhythmAnalyzer / BeatTracker
1条回退分析不了就退回淡化，并写明原因
一句话形态：设置 › 播放与换源 › 切歌过渡，总开关 + 两档方式。智能过渡下单首第一次播时先把下一首排进分析队列；切歌时按分析结果挑接法，播放页可选画一个过渡圆环或封面描边；拿不到完整音频就退回固定淡化，设置页留一行「上一次接歌」说明用了什么、为什么退回。
01

对照代码逐条核对，只做现在没有的部分。已有的能力不重做，只在能复用的地方复用。

02

两档模式与行为规则

总开关按功能叫「切歌过渡」，两档沿用参考里的名字：交叉淡化和智能过渡。「过渡最长时长」只在交叉淡化下出现，智能过渡自己决定每次多长。

模式做法什么时候用
交叉淡化歌尾最后 4 / 6 / 8 / 10 秒等功率淡出，下一首同时淡入。曲线固定，不分析。任何歌、任何来源，永远可用
智能过渡先分析两首歌的节拍、速度、调性、响度、首尾和段落，再从切拍、低频交接、尾奏承接、等功率淡化里挑一种；必要时做速度对齐、频段交接、回声收尾。能在切歌前拿到下一首完整音频时

几条不跟参考走、但要先定下来的规则

  • 手动切歌固定 1.2 秒等功率淡化，不做智能过渡、不画动画——参考也说明手动切歌时过渡来不及展开。
  • 睡眠定时淡出优先：定时结束前的那段淡出期间不再启动过渡，避免两条音量曲线打架。
  • 队列最后一首不接；单曲循环不接。
  • 失败即回退：分析没完成、预载换源失败、主副播放器对齐误差超过 30 ms，都退回等功率淡化，不硬做切拍。
  • 过渡长度：交叉淡化 4–10 秒；智能过渡 1.2–12 秒，由接法决定。短于 5 秒不画动画（照参考）。
和现有功能的关系：音量均衡先按平台的 gain / peak 归一，再做过渡，避免交接处响度跳变；离线分析的拍网格和律动跟拍的实时网格各自独立，互不覆盖。
03

设置界面稿

位置放在设置 › 播放与换源最上面，原来的页面副标题扩成「切歌过渡、换源模式与平台顺序」。组件全部沿用现有的：SectionLabel、SwitchRow（64dp、40dp 圆形图标）、ConnectedToggleGroup（48dp，选中项满圆角）、ListRow、InfoNote、SettingsNote；颜色取 #006B5F 种子的 M3 浅色方案。

电视和平板：不另做一套。设置页同一组组件，圆环画在封面上；电视遥控器按任意键消失。减少动画打开时，两种动画都不画，过渡照常。
04

什么时候能做智能过渡

参考里「完全体 / 兼容模式」的分界是能不能在本地解码分析。落到我们的播放链路，分界就是切歌前能不能拿到下一首的完整音频。

来源切歌前拿到整首结果
本地文件 / 已下载能智能过渡
Navidrome / OpenSubsonic能智能过渡
在线歌曲，已缓存能智能过渡
在线歌曲，未缓存提前预取，来得及就能来得及智能过渡；来不及退回交叉淡化
Apple Music 整曲（Widevine）不能，必须边解边播交叉淡化
云听等直播流不能，也没有下一首不接
试听片段（30 秒）能，但片段本身不完整交叉淡化
预取不额外多耗流量：下一首本来就要播，只是提前到当前歌播放时下载。预取走现有媒体缓存；连续快速切歌时取消没用的预取。
05

分析怎么跑

不下载模型，也不做音轨分离。节拍、速度直接复用已经跑在播放链路上的 RhythmAnalyzer 和 BeatTracker，把输入从「AudioSink 正在播的 PCM」扩成「离线解码出来的 PCM」。

排进队列当前歌开始播时，把下一首放进分析队列；切歌、换源就取消旧的。
拿音频本地直读；在线先看缓存是否完整，不完整就后台补全整首。
离线分析PCM 依次过 FFT、起拍、拍网格，再算响度、chroma 调性、首尾静音和能量分段。
存下来按歌曲 key + 音频长度 / 指纹写进 Room；下次播同一首直接读。

每种接法要什么数据

接法用到的分析怎么接
切拍两首的拍网格、小节首拍下一首的第一个小节首拍对齐当前歌的下一个首拍，重叠只留 0.8–1.5 秒短淡化
低频交接低频能量、两首的调性出曲低通下潜、入曲高通抬起，低频在中间交接；调性差太多就只交接不叠拍
尾奏承接尾奏长度、前奏长度、响度入曲从 intro 前段接进，出曲尾奏自然收；必要时加回声收尾
等功率淡化响度余弦 / 正弦曲线，按两首的响度差补偿增益

分析结果的字段

// AutomixAnalysis，按 song.key 存在 Room
val bpm: Double              // 拍网格周期推出来
val beatGrid: BeatGrid        // 复用现有类型：t0 / period / downbeat / confidence
val key: Int                 // 0–11 + 大小调，来自 chroma
val loudnessLufs: Float
val introMs: Int              // 第一个有效声音
val outroMs: Int              // 最后一个有效声音
val sections: List<Section>   // 能量分段，给尾奏承接挑位置
val analyzedAt: Long
首次要等几秒：一首歌第一次播放时分析在低优先级线程上跑，不打断播放。结果存下来后同一首不再分析；音频文件变了（重新下载、换源到不同版本）才重分析。
06

播放侧怎么接

Media3 没有内置的歌曲交叉淡化。做法是双实例：当前歌一个 ExoPlayer，下一首提前在第二个实例里预载；到过渡点同时出声，各自跟音量包络，结束后把主播放器整体换到第二个实例。

关键点

  • 换主播放器：过渡结束后把队列剩余重建到新实例，MediaSession.setPlayer() 过去，睡眠定时、律动分析、DRM session 管理器一起跟过去，旧实例释放。这是本方案改动最大的一块，P1 就要先做出来。
  • 两路 AudioTrack 有固定延迟差：切拍前用一次静音测距校准（和跟拍校准同一个思路），误差超过 30 ms 就不做切拍，退回等功率淡化。
  • 频段交接：在各自的 AudioProcessor 链里加二阶 biquad，高通 / 低通扫频；音量均衡的 VolumeGainAudioProcessor 排在它前面。
  • 速度对齐：PlaybackParameters 变速不变调，两首 BPM 差在 ±6% 以内才用；超过就只淡化，不硬拉。
  • 回声收尾：只在尾奏承接时给出曲加反馈延迟，尾段淡出时留一条尾巴；其他接法不加。
  • 预载失败就回退：下一首在第二个实例里换源失败、或分析还没跑完，直接走等功率淡化，播放页的音源提示照旧。
// 过渡点：两首的时间轴对齐后，同时开始各自的包络
val plan = AutomixPlanner.decide(current, next)   // 返回接法 + 起止时刻 + 曲线
outgoing.playbackParameters = plan.outgoingTempo
incoming.playbackParameters = plan.incomingTempo
outgoing.volume = 1f; incoming.volume = 0f; incoming.play()

// 每帧按 plan 推进两条曲线；结束时把 session 交给 incoming
onTransitionEnd { handOffSession(from = outgoing, to = incoming) }

过渡动画

照参考只做两种，外加关闭。动画只是把这次混音画出来，不参与任何决策。

选项表现
关闭不画
屏幕圆环围着封面画一整圈，进度段随过渡推进；下面一个小胶囊写「接法 · 时长」。点按（电视按任意键）立刻消失，本次切歌不再出现。
封面描边沿封面形状的外轮廓走一圈，进度段 primary、剩余 outlineVariant。只在播放页画；播放条上没有封面就不画。
  • 短于 5 秒的过渡不画（参考一致）。
  • 打开「减少动画」或系统移除动画：两种都不画，过渡本身照常。
  • 电视 30 帧上限下按真实时间推进，和律动跟拍同一个处理方式，最多晚一帧。

分四步做完

先把能回退的底座做出来，再加分析，最后才是接法和动画。每一步单独可用。

P1

交叉淡化

  • 设置块、总开关、两档方式
  • 第二实例预载 + 等功率包络
  • 换主播放器、队列与 MediaSession
  • 手动切歌 1.2 秒淡化
P2

离线分析

  • 离线 PCM 解码 + 复用 BeatTracker
  • 响度、chroma、首尾、分段
  • Room 缓存与预取
  • 「上一次接歌」与回退原因
P3

四种接法

  • 切拍、低频交接、尾奏承接
  • 速度对齐、频段交接、回声收尾
  • 双路延迟校准
  • 失败回退链路
P4

动画与收尾

  • 屏幕圆环、封面描边
  • 减少动画、电视 30 帧
  • 缓存不足提示与入口
  • 手机 / 平板 / 电视核对
09

不做的事

  • HTDemucs 人声分离、表现模式、人声退场：手机上跑分离不现实；参考里依赖它的两项连同「表现模式」一起不做。
  • Beat This! 模型：不下载、不附带模型，节拍用现有 DSP。
  • 浏览器兼容模式：没有浏览器端，不搬。
  • 桌面端的命令面板入口：设置里直接放开关和两档方式。
  • 让「过渡最长时长」作用于智能过渡：参考明确它只在固定淡化下生效，这里保持一致。
