没歌在播时，底栏浮起来

底栏按「有没有歌在播」分成两种形态：有迷你播放器时沿用现在的 ShortNavigationBar，和播放器组成一组贴底；没有迷你播放器时换成 HorizontalFloatingToolbar，单独浮在内容上。FloatingToolbar 的尺寸按库里的实值画：高 64dp、内边距 8dp、离屏幕边 16dp、形状 CornerFull、标准色 surfaceContainer。

两种状态

分界线是「有没有歌在播」

前两个是最终的规则：有迷你播放器 → 导航栏贴底；没有 → FloatingToolbar 悬浮。后两个是 FloatingToolbar 的两种宽度可选（默认收缩居中，或撑满留 16dp）。

规格

库里的实值

下面这些不是估的，是从 material3-1.5.0-alpha25 的 FloatingToolbarTokens 和 ElevationTokens 里读出来的。

Token值含义
ContainerHeight64dp和现在的导航栏一样高
ContainerExternalPadding16dp离屏幕左右边、底边的距离（FloatingToolbarDefaults.ScreenOffset）
ContainerLeadingSpace / TrailingSpace8dp内容四周的内边距
ContainerBetweenSpace4dp槽位之间的间距
ContainerShapeCornerFull全圆角（64dp 高 → 32dp 半径，胶囊）
StandardContainerColorSurfaceContainer和现在导航栏同一色，配色不用改
VibrantContainerColorPrimaryContainervibrant 变体
ContainerExpandedElevationLevel0 = 0dp这一点和文档常说的“默认有 elevation”不一样：这版展开态是 0dp
ContainerExpandedElevationWithFabLevel1 = 1dp只在配 FAB 时才有 1dp

代码怎么改

PhoneBottomBar.kt 里按 state.current != null 分支：有歌在播照旧用 ShortNavigationBar（这段一行不动），没歌在播用 HorizontalFloatingToolbar。缩起的 toolbar 不留 16dp 竖向 padding，否则会多出一条空白。

// PhoneBottomBar.kt —— 按有没有歌在播切底栏
if (state.current != null) {
    // 有迷你播放器：现有导航栏，贴底满宽，和播放器组成一组
    ShortNavigationBar(
        modifier = Modifier.frosted(if (blur) container.copy(alpha = .72f) else container),
        containerColor = Color.Transparent,
        windowInsets = WindowInsets.navigationBars,
    ) { /* 四个 ShortNavigationBarItem 不变 */ }
} else {
    // 没有播放器：悬浮 FloatingToolbar 自己贴底
    HorizontalFloatingToolbar(
        expanded = true,
        modifier = Modifier
            .fillMaxWidth()
            .padding(horizontal = 16.dp)
            .padding(bottom = 16.dp + navInset),
        colors = FloatingToolbarDefaults.standardFloatingToolbarColors(),
        contentPadding = FloatingToolbarDefaults.ContentPadding,
    ) {
        TopTab.entries.forEach { tab ->
            val on = selected == tab.route
            FilledIconButton(
                onClick = { onSelect(tab.route) },
                modifier = Modifier.weight(1f),
                colors = if (on) FilledIconButtonDefaults.filledIconButtonColors(
                    containerColor = MaterialTheme.colorScheme.secondaryContainer,
                ) else IconButtonDefaults.filledIconButtonColors(
                    containerColor = Color.Transparent,
                ),
            ) {
                Icon(if (on) tab.selectedIcon else tab.icon, tab.label)
            }
        }
    }
}

留白要跟着分支算

phoneOverlayHeight() 现在是 64 + 迷你播放器。加一个参数区分两种状态：有播放器时 = 64 + 8 + 64 + 8；没有时 = 64 + 16 + 16，其中 16 是 FloatingToolbar 离屏幕的边距。AppNavigation.kt:294 靠它算内容底部留白，不分支会把列表最后一行压住。

叶子页面不受影响

播放页、海报墙、设置子页这些叶子页面本来就盖住底栏，分支只在主界面这一处生效，不用挨个页面改。

只有 toolbar 那支会丢无障碍状态

ShortNavigationBarItem 自带 pill 指示器、标签语义、selected 状态。FloatingToolbar 槽位里要自己补：选中底色、Role.Tab、selected 语义、读屏文案。有播放器的那支完全不受影响。

规范上仍然有重叠

Toolbars Guidelines 说 toolbar 和导航栏都在窗口底部、不能同屏，toolbar 装的是当前页动作。按这个规则，没歌在播时用 FloatingToolbar 装四个顶层目的地，等于用 toolbar 承担导航职责。这是你要的方案，我照做，只在这里记一笔。
