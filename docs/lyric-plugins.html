全屏歌词动画：原生移植 Folia 的歌词模组

01结论：不加载模组，把相关的部分原生重写

Folium v1.x 的模组是 ES 模块，靠 DOM、Canvas 2D、WebGL 画画面。Android 上想原样运行只有两条路：套 WebView，或者内嵌 QuickJS 一类的 JS 引擎再自己实现一遍 DOM 和 Canvas。前者已经排除；后者也是新增组件，而且要补的浏览器 API 比重写这几个模组还多。所以这里不做加载器，只移植效果，同时把 Folium 的几个接口（歌词动画模式、设置表、宿主图层开关、歌词变换、播放页图层）照搬成 Kotlin 接口。

零新依赖

只用系统和现有库

画面用 Compose Canvas、TextMeasurer、RenderEffect（Android 12+）、RuntimeShader（Android 13+）；简繁转换和罗马音转写用系统自带的 ICU（Android 10+）。不加库、不加数据文件、不联网。

不动态加载

每个模式就是一个 Kotlin 类

不下载代码、不用 DexClassLoader，模式跟版本一起发布。来源模组、版本、作者和许可写进 THIRD_PARTY_NOTICES。

默认不变

不打开就和现在一样

全屏歌词页默认还是“经典”，也就是现在的 LyricsList。歌词文字的几项转换都默认关，通知栏和桌面小组件的歌词照旧。

系统 ICU 实测（模拟器上用 app_process 跑 dex 探针）：一共 791 个转写器，Hans-Hant、Han-Latin、Hiragana-Latin、Katakana-Latin、Hangul-Latin、Cyrillic-Latin 都有。

「我们头发里的风，后来干了」→「我們頭髮里的風，後來乾了」：逐字转换，大部分对，但「里」没有变成「裡」。系统 ICU 没有 OpenCC 那样的词组表，所以设置里要写明“个别字转不准”。

韩文「사랑해요」→ salanghaeyo，俄文「Катюша」→ Katûša，都不是常用拼法。日文汉字会被当成汉语拼音读（「風の中で」→ fēngno zhōngde），所以自动转写只处理不含汉字的行。

04交互稿：全屏歌词页

手机的全屏歌词页。歌词和节拍都是模拟的（自拟歌词、112 BPM）。上面一排切模式，右上角 ✦ 打开动画面板。配色用播放页的深色 Vibrant（PlayerTheme），控件照现有组件画：顶栏小圆封面 + 标题 + 收藏、WavySeekBar、Compact 按钮组、浮动工具栏。舞台铺满整页，文字排在顶栏和控件之间的安全区里，背景类的效果可以铺到安全区外面。

入口放在哪

  • 手机：全屏歌词页顶栏，收藏左边加一个 ✦ 图标按钮（48dp，和收藏同款）。底部工具栏现在是“歌词、队列”两项，再加一项总宽是 168 + 156 = 324dp，正好等于 360dp 宽手机的可用宽度，更窄的屏放不下，所以不放那里。
  • 平板、横屏：工具栏空间够，在“歌词”后面加一项 ToolbarIconButton。
  • 电视：更多菜单加“歌词动画…”，打开右侧 360dp 的面板。
  • 所有设备：设置 → 播放页里也有同一个入口。

点舞台：经典模式和现在一样，点一句跳过去；别的模式没有逐句列表，点一下只唤醒控件。首次进入时 ✦ 外面有一圈呼吸提示，打开过一次就不再显示。

06电视

电视的全屏歌词（环境模式）整屏给舞台，右上角保留时钟。和手机同一套模式、同一份设置，区别只在这几处：画面限 30 帧（现有 TvFrameGate）；没有触摸，点不了舞台；星星数量、同时存在的年轮数按六成算；面板是右侧 360dp，遥控器上下键在面板里移动焦点。

电视画面和手机共用同一个模拟时钟，这里每两帧画一次，模拟 30 帧。

07各模式移植说明

效果描述和数值来自各模组源码。“面板”一列是放进动画面板的设置项数，其余保持原默认值。工作量按“小 ≈ 1 天、中 ≈ 2–3 天、大 ≈ 4 天以上”估，含手机、平板、电视三处检查。

/** 一个歌词动画模式。编进 APK，不动态加载。 */
interface LyricVisualizer {
    val id: String                     // "rings"，存进设置
    val label: String                  // "52Hz"
    val origin: ModOrigin?             // 来源模组、版本、作者、许可；经典为 null
    val order: Int
    val settings: List<LyricSetting>
    val hostBackground: Boolean get() = true   // false：画自己的 Background
    val hostSubtitles: Boolean get() = true    // false：模式自己排翻译，宿主副行让位
    val wantsAudio: Boolean get() = false      // true 才去开 RhythmAnalyzer

    fun subtitleInset(ctx: LyricStageContext, stage: Size, density: Density): Float = 0f
                                     // 模式占了安全区底部（巨幕的跑马灯带）时副行往上让多少像素，宿主在副行的布局阶段调

    @Composable fun Background(ctx: LyricStageContext) {}
    @Composable fun Stage(ctx: LyricStageContext, modifier: Modifier)
}

sealed interface LyricSetting {
    val key: String; val label: String; val summary: String?
    data class Number(..., val min: Float, val max: Float, val step: Float,
                      val default: Float, val format: (Float) -> String) : LyricSetting
    data class Choice(..., val options: List<Pair<String, String>>, val default: String) : LyricSetting
    data class Toggle(..., val default: Boolean) : LyricSetting
}

@Stable
class LyricStageContext(
    val lines: List<StageLine>,       // 带句末时间；没有逐字时间的按句长均分
    val song: Song,
    val seed: Long,                    // 由歌曲 key 算出，随机效果可复现
    val clock: StageClock,             // 帧精度歌词时间，含用户偏移
    val lineIndex: State<Int>,         // 句间为 -1
    val paused: State<Boolean>,
    val colors: StageColors,           // PlayerTheme 颜色 + 封面主色
    val display: StageDisplay,         // 字号档、控件空闲、减少动态效果、电视、安全区
    val settings: SettingValues,       // 已合并默认值、已夹紧
    val audio: StageAudio?,            // wantsAudio 才有：power、bass、mid、treble、kick、beat、bands(48)
)

interface LyricStageLayer {               // 频谱
    val slot: StageSlot                  // Back / Front
    @Composable fun Layer(ctx: LyricStageContext, modifier: Modifier)
}

09歌词变换

现在 LyricsParser.parse 有 3 个调用处：播放页、通知栏歌词（MusicViewModel）、桌面小组件（WidgetLyrics）。统一换成 LyricPipeline.prepare(raw, prefs)，三处看到的歌词一致。和 Folium 一样，每次都从原始歌词重新算，关掉开关就回到原样，不存改写后的结果。顺序：

  1. 解析：现有逻辑，只改一处：同一时间戳有三层时，中间那层存成 romanization。现在 mergeLayers 取最后一层当翻译，注释写的顺序是“原文、罗马音、翻译”，罗马音就被丢掉了。
  2. 拆单行双语（lyric-split-translation 的规则）
    • 分隔符：/ ／ ｜ | //，先统计全曲出现最多的那个，只用它。
    • 先整首评估：系数 =（能拆的行 + 4）/（总行数 − 剔除行），大于 0.8 才动手。剔除空行、只有分隔符的行、间奏标记。
    • 逐行：分隔符在行首或行尾的不拆，拆出来两段都要非空；已经有翻译的行不覆盖。
    • 整首判定这一步是为了不误伤歌词本身里的斜杠，比如“AC/DC”。
  3. 简转繁：Transliterator.getInstance("Hans-Hant")，原文和翻译都转。含假名的行跳过，避免把日文汉字转坏（opencc 模组的 protectJapanese 也是这个意思）。Android 9 及以下没有这个类，开关灰掉。
  4. 罗马音：优先用歌词自带的那层。打开“自动转写”且该行没有罗马音时，只处理不含汉字的行：韩文 Hangul-Latin、假名 Hiragana/Katakana-Latin、西里尔 Cyrillic-Latin。拼法和常见写法不同，所以默认关。

每一步都是纯函数，单元测试直接喂字符串：拆分的系数边界、分隔符在行首行尾、三层时间戳、含假名跳过繁体转换。

10自动切换

固定

默认

所有歌都用面板里选中的模式。

随机

lyric-style-switcher

每首歌随机换一个，不和上一首重复；记住每首歌抽到的，再听时一样（最近 2000 首）。

按速度

bpm-style-director

四档速度各对应一个模式，左闭右开。BPM 用 BeatTracker 的结果，置信度到 0.5 才算锁定；没锁定前保持当前模式。测到的 BPM 记下来，下次这首歌一开始就能换。

  • 什么时候换：第一句之前还剩 0.4 秒以上，或者两句之间空当至少 1.5 秒、离下一句还有 0.8 秒以上。都不满足就等到下一首，绝不在一句唱到一半时换。
  • 手动优先：自动模式下用户在面板里点了某个模式，这首歌就不再自动换。“这首歌固定用它”开关写进 pins，以后每次都用。
  • AI 导演不做：要用户填自己的大模型地址和密钥，还要把歌名、歌词发出去。

11性能与边界

  • 一个帧循环：舞台里只有一个 withFrameNanos，时钟只在绘制阶段读，不触发重组（KaraokeLine 现在就是这样）。页面不可见、App 退到后台时循环停。
  • 音频按需：只有 wantsAudio 的模式（52Hz、星潮）和频谱图层打开时才调 RhythmAnalyzer.capture，离开页面就释放。“律动”背景本来就在采集时共用同一路。
  • 文字量一次：每句的排版按“句子 + 字号 + 宽度”缓存，逐字位置只在换句或旋转屏幕时重算。
  • 版本兜底：模糊只在 Android 12+ 用 RenderEffect，以下改成透明度过渡；AGSL 只在 13+，以下走 Path 版本。minSdk 23 的设备所有模式都能用，只是少些效果。
  • 电视：30 帧，星星和年轮按六成数量画。
  • 减少动态效果：系统关了动画（动画时长缩放为 0）时，每个模式每句只画一张静帧。
  • 读屏：舞台对外是一个文本节点，内容是当前整句加翻译，不逐字播报。
  • 没有歌词：纯音乐、电台直播。52Hz 照原版从随机髓心长年轮，黑胶只转唱片，星潮只有星空；其余模式显示和经典一样的“暂无歌词”。
  • 没有逐字时间：按 52Hz 的规则，句长的 85% 均分给每个字。
  • 长句：最多 3 行，放不下就把字号乘 0.88 再试，最多 6 次。
  • 折叠屏：桌面姿态上半屏是歌词时同样用 LyricStage，安全区换成上半屏；铰链分栏时舞台只在歌词那一栏。
  • 小窗：高度不到 320dp 时自动退回经典，不保存这次退回。
