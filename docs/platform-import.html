01 · 要解决什么

登录之后，顺手把已有的歌单拿过来

issue 里问的是「既然已经可以登录平台账号，是不是可以直接同步平台歌单」。直接改成「登录即全量同步」太重且不可逆，先做一步：登录成功后问一次要不要把平台歌单导入。导入的每一条都走已有的绑定流程，所以之后平台那边增删歌、这里会自动跟上。

链接导入歌单后歌曲不完整，整个歌单有几百首歌导入后只有三首。另外既然已经可以登录平台账号，是不是可以直接同步平台歌单。 —— mytv-android/myMusic#21
弹一次，不打扰只在这个平台第一次登录成功时弹；关掉、点「以后再说」或者「不再询问这个平台」之后不再自动弹。settings: promptImported[providerId]
导入 = 绑定每一条都落到已有的 bindPlatformPlaylist：平台更新自动同步、能写回、会跟着同步走。MusicViewModel.bindPlatformPlaylist
已有的不重复已经绑过同一平台歌单的直接跳过并标「已绑定」；同名普通歌单会被升级成绑定（bindingTarget 的既有行为）。data/BoundPlaylists.kt
02 · 什么时候弹

登录成功 → 拉一次列表 → 有东西才弹

扫码和密码两条登录路径最终都落在 MusicViewModel 里写 Cookie 的地方（startQrLogin 的 success 分支、saveCookie）。在这里判断「换成了一份新的非空 Cookie」再触发，避免退出登录、粘贴旧 Cookie 也弹。

时刻做什么弹不弹
扫码 / 密码登录成功写 Cookie，一次 userPlaylists(provider, cookie, 1, 100)弹 前提：列表非空、这个平台没被关掉
用户粘贴了 Cookie同上（Cookie 确实变了才算）弹 同一条规则，手动粘贴不排除
退出登录写空 Cookie不弹
登录成功但拿不到歌单接口报错 / 空列表（新账号、平台不支持）不弹 静默，别用基础错误打断用户
这个平台以前点过「不再询问」—不弹
为什么不在登录面板里直接嵌「导入」：扫码面板的宽度是按二维码定的（手机 220dp），塞不下 100 条歌单；登录和导入是两个决定，分开弹用户能先关掉导入、继续用应用。列表要拉一次网络，在面板里等会让「登录成功」的反馈变慢。
03 · 界面

一个面板，全设备共用一个 AdaptiveSheet

沿用现在在用的组件，不新造样式：外壳是 AdaptiveSheet（手机底部面板 / 平板右侧 400dp 浮动面板 / 折叠屏书本只占右页 / 电视右侧 360dp 整高）；列表行照「从文件导入」的 ImportListRow（勾选框 + 名字 + 首数 + 平台小块）；顶部是全选切换 ConnectedToggleGroup；底部主按钮 Button 26dp 圆角；歌单行右侧的「已绑定」用 Tag。

04 · 边界与文案

哪些情况要提前说清楚

情况界面怎么表现导入后
歌单已经绑过行灰掉、勾选框不可点，右侧 已绑定不动
同名普通歌单已存在行下面写「会合并进同名歌单」bindingTarget 升级成绑定，内容以平台为准
平台不给私人歌单（Apple / 部分源）这条平台不出现，不出空分组—
拉列表失败 / 超时不弹；在平台账号行 ⋮ 里仍可手动打开，面板内出重试—
一次导入很多（上百首）按钮变成「正在导入 3/12…」；面板不关全部完成出一条「已导入 12 个歌单 · 803 首」
导入中按返回照 SheetDismissGuard 拦：问「导入还在进行，确定离开？」已完成的保留，剩下的取消
