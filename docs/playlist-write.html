调研与方案 · 2026-11-09

绑定歌单也能改：增删与排序写回平台

现在在绑定歌单里加一首、删一首、挪一下位置，都会先自动解除绑定，歌单从此变成手动副本。 这次把各平台的写接口摸了一遍：网易云可以增删但没有歌单内排序接口；QQ 音乐、酷狗三项都能写； 其余平台没有找到可用的写接口，继续沿用“编辑即解绑”。方案的核心不是调接口，而是先把本地歌曲解析成平台曲目 ID， 写成功后再回读，失败则回滚。

网易云 增 / 删 QQ 音乐 增 / 删 / 排序 酷狗 增 / 删 / 排序 其他平台 无写接口，保持解绑
结论

先做三个平台，其他平台不硬凑

调研覆盖了 App 里能绑定歌单的全部来源。可写的前提有三个：平台有非公开但稳定的写接口、App 已经持有对应登录态、 本地歌曲能被解析成该平台曲目。三个条件同时满足的只有网易云、QQ 音乐和酷狗。

3 个平台网易云、QQ、酷狗可写回；前两者已有登录态与请求通道。P1 网易云 · P2 QQ · P3 酷狗
排序是分水岭QQ 与酷狗接受“整张歌单的新顺序”；网易云没有歌单内排序接口。网易云只做增删
跨源添加要先匹配从别的平台或本地音乐加进来的歌，先搜索目标平台并严格匹配。复用 TrackMatcher 0.92
不引入离线队列写平台必须在线；失败就回滚，不排后台任务，避免多设备分叉。平台为准，先写后更
一句话方案：绑定歌单的编辑不再解绑。操作时先把歌曲解析成目标平台曲目，调用平台写接口， 成功后回读整张歌单覆盖本地并标 dirty；失败则恢复操作前的本地内容并提示原因。 平台不支持排序或不是自己的歌单时，界面提前变成只读，而不是让用户改完才发现写不回去。
现状

绑定是只读镜像，一编辑就断链

绑定功能（fdc48da）把平台歌单落成本地歌单，靠 15 分钟节流从平台拉最新内容。 任何本地编辑都会在写库前调用 unbindIfBound，把绑定字段清空并提示“改为手动维护”。 这套设计解决了“快照副本”的问题，但没有解决“把本机当遥控器”的诉求。

现状锚点行为影响
MusicViewModel.addSongToPlaylist先 unbindIfBound，再写本地条目加一首歌，整张歌单失去绑定
removePlaylistEntries / movePlaylistEntry同样先解绑删歌、调顺序都会断链
refreshBoundPlaylist拉平台内容 replaceEntries 覆盖本地，15 分钟节流本地顺序完全跟随平台

绑定数据在 playlists.link_provider / link_id / link_cover / link_synced_at。 写回平台不需要新增表；真正缺的是“平台曲目 ID”和“歌单可写元数据”，这两样都能在操作时取到，不必改库结构。

证据与实现细节

网易云

增删走 POST https://music.163.com/api/playlist/manipulate/tracks，表单参数 op（add / del）、pid、trackIds（JSON 数组字符串）、imme=true。 重复添加时接口会回 code=512，按“已存在”处理即可。

排序没有对应接口。/api/playlist/order/update 虽然存在，但参数只有 ids、没有 pid， 文档语义是“调整歌单顺序”（我创建的歌单之间的顺序），不是歌单内曲目顺序。网易云 Web 端也只有 playlist/manipulate/tracks 一个写接口，页面没有拖拽排序。

来源：NeteaseCloudMusicApi 镜像的 module/playlist_tracks.js、module/playlist_order_update.js； 网易云 Web 核心 JS 中仅出现 /api/playlist/manipulate/tracks。

QQ 音乐

新版接口在 u.y.qq.com/cgi-bin/musicu.fcg，模块 music.musicasset.PlaylistDetailWrite：

  • AddSonglist：dirId、tid、v_songList（songId + songType）
  • DelSonglist：同样的曲目对
  • SeqSonglist：v_songPair，必须提交歌单内全部歌曲的新顺序

排序只提交部分歌曲时服务端仍返回成功，但未提交的歌曲顺序会被打乱；提交不存在的歌曲回 80095。 旧接口 fcg_music_add2songdir.fcg（按 songmid）和 fcg_music_delbatchsong.fcg（按 songid） 仍可用，可作降级。

来源：L-1124/QQMusicApi 的 qqmusic_api/modules/songlist.py；jsososo/QQMusicApi 的 routes/songlist.js。

酷狗

云歌单服务（cloudlist.service.kugou.com，Android 加密通道）：

  • 添加 /cloudlist.service/v6/add_song：listid、name / hash / album_id / mixsongid
  • 删除 /v4/delete_songs：fileid 列表
  • 排序 /v1/modify_song_sort：fileid|sort 列表、list_ver、type

App 的 KugouProvider 已经有同一套 androidHeaders + AES 加密与云歌单详情解析， 写接口可以直接复用；缺的是详情响应里的 fileid 与 list_ver 字段。

来源：MakcRe/KuGouMusicApi 的 module/playlist_tracks_add.js、playlist_tracks_del.js、playlist_tracks_sort.js。

为什么不做其他平台

酷我 Web 端只有歌单信息与推荐接口，收藏动作会引导下载客户端；公开实现里没有写接口。 咪咕、千千的第三方库只覆盖搜索、详情与播放地址。汽水走私有签名器，写接口需要逆客户端。 B 站收藏夹虽然能加删，但对象是视频/音频稿件，无法把网易云的歌映射过去。

来源：KuwoMusicApi 现有实现、汽水与咪咕第三方库的接口清单、bilibili-API-collect 的收藏夹文档。

可信度：三个平台的接口都来自仍在维护的第三方实现，不是官方文档。上线前必须在真机用真实账号跑通一遍 （见文末核对清单）；接口失败时按“平台不支持”降级为解绑，而不是让用户卡住。
难点

真正要解决的五件事

1. 本地歌曲不是平台曲目

歌单条目里存的是 Song，身份是 source:id。绑定网易云时，从网易云拉进来的歌天然带网易云 track id；但从 QQ、本地音乐或聚合搜索加进来的歌，source 不是 netease，平台接口不认。 写之前必须先得到目标平台的曲目 ID。

解析顺序：同源直接用 → 查 canonical_sources 是否已有该平台的版本 → 按“歌名 + 歌手”搜索目标平台，用 TrackMatcher 严格模式（0.92）取最佳结果。 三条都不成立就跳过这首歌，汇总提示“有 N 首在网易云没找到”，不阻断其他歌曲。

2. 不是所有歌单都能改

平台只允许改自己创建的歌单。收藏的别人的歌单，写接口会返回权限错误；界面上现在完全看不出来。 需要在打开绑定歌单时做一次归属判断：

  • 网易云：用户歌单接口的 subscribed 为 false，或详情里的 creator.userId 等于当前账号。
  • QQ：在 userPlaylists 返回的自建歌单里能找到这个 dissid（同时能拿到 dirid）。
  • 酷狗：云歌单 type=0（自建 / 我喜欢）可写；type=1（收藏）不可写。

判定为不可写时，详情页显示“只读 · 不是你的歌单”，隐藏编辑、添加与排序入口，保留“立即同步”“解除绑定”。

3. 排序不是“挪一下”，而是提交整张歌单

QQ 的 SeqSonglist 和酷狗的 modify_song_sort 都要求提交完整顺序。单次移动要在本地先算出 新顺序，再整表推送；连续点上下移不能每次都发请求。做法是本地即时重排 + 500ms 防抖，只推送最后一次完整顺序。

酷狗还带 list_ver 版本号：别的客户端刚改过歌单时版本会不匹配。收到冲突后重新拉一次详情， 把本地顺序合并到新内容上再试一次，仍失败就回滚并提示“歌单已在其他设备变化，请重试”。

网易云没有排序接口，编辑模式不显示上移/下移与拖拽，提示“网易云歌单不支持在 App 内调整顺序”。

4. 平台写与 15 分钟刷新会抢同一条记录

现有 playlistMutex 已经串行化所有歌单编辑与刷新。写平台是挂起操作，必须继续走同一把锁： 有写操作在途时，自动刷新直接跳过；写成功后由写操作自己回读并更新 linkSyncedAt。 这样不会出现“刚删完，刷新又把歌加回来”。

5. 撤销变成反向写

现有移除操作带撤销（restoreEntry），只写本地。绑定歌单的撤销必须反向调用平台：移除的撤销 = 加回， 移动的撤销 = 再排一次。能排序的平台顺带恢复到原位置；网易云只能追加到末尾。撤销失败时明确提示，不静默吞掉。

方案

平台为准，先写后更

不引入后台队列、不做离线编辑、不在本地先斩后奏。每次操作都是一次完整的“校验 → 解析 → 写平台 → 回读 → 落库”， 失败则回到操作前。这样多设备、刷新、撤销都只有一种真相：平台。

校验登录态、歌单归属、平台能力；不可写直接给只读态
解析曲目同源 ID → canonical → 搜索匹配；找不到的跳过并汇总
调平台增删按批；排序推送完整顺序，酷狗带 list_ver
回读重新拉整张歌单，平台顺序与元数据为准
落库覆盖本地条目，更新 linkSyncedAt，标 dirty 推同步
失败回滚恢复操作前条目；提示原因，提供“存本机并解绑”

  • 单测：归属判定、顺序合并、错误映射
核对清单

上线前必须真机验证的项

网易云

  • /api/playlist/manipulate/tracks 在本 App 的 UA / IP 下可用，Cookie 只需 MUSIC_U + __csrf
  • 重复添加返回 512 时按成功处理
  • 自建歌单与收藏歌单的 subscribed / creator 判定准确
  • 歌单曲目上限（1000 / 2000）与分批大小
  • 桌面客户端是否真的支持歌单内排序（如支持，抓包补接口）

QQ 音乐

  • dirid 能从自建歌单列表稳定拿到；我喜欢 = 201
  • SeqSonglist 全量提交后 Web 端顺序一致
  • 缺歌 / 越权时错误码（80092 / 80095）与文案
  • 登录态只需 uin + qqmusic_key + g_tk；二维码登录拿到的 cookie 足够
  • 旧接口在会员歌曲上是否仍可添加

酷狗

  • 云歌单详情是否返回 fileid 与 list_ver
  • add_song 的 mixsongid / album_id / hash 三件套是否必需
  • type=1 收藏歌单写操作的错误表现
  • token 过期后的错误码与重新登录提示
  • 排序 sort 的取值规则（0 起还是 1 起）

通用

  • 严格匹配 0.92 对现场版 / remix 的误配率
  • 写操作在途时自动刷新确实被跳过
  • 写成功后多设备同步与平台回读内容一致
  • 撤销在增删、排序、批量三种路径都能反向写
  • 平台接口失败不会把本地歌单清空（回滚覆盖所有分支）
风险

需要提前接受的代价

  • 非官方接口：三个平台都没有公开文档，接口可能随客户端升级变化。实现上按“失败即降级为解绑”兜底，不把用户卡死在写不出去的歌单里。
  • 账号风险：高频写歌单与官方客户端行为不同，理论上存在风控可能。批量操作限制单批数量、失败不自动重试风暴。
  • 匹配误差：跨平台加歌只能靠歌名与歌手匹配。严格阈值会漏掉别名，宽松会加错版本；首版接受漏配，不做模糊兜底。
  • 网易云没有排序：这不是实现取舍，是接口缺失。不要在“删除全部再按新顺序加回”上做文章，那会改变添加时间，失败还会把歌单清空。
  • 只读歌单占多数：用户收藏的大多是别人的歌单，写功能真正生效的是自建歌单；界面必须提前说明，避免“为什么不能改”的困惑。
