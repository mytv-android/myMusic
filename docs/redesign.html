总览

首页不再承担所有事情。

现在的首页同时放推荐歌单、排行榜、歌单分类和热门歌曲，导致“发现”这件事没有单一入口。新结构把首页拆成两个明确任务：榜单回答“现在什么在流行”，歌单回答“我想听一组什么歌”。音乐库升级为“我的”，成为收藏与自建歌单的家。

“首页”不是改名，而是被拆掉了。平台排行榜归入榜单，推荐歌单与分类归入歌单，热门歌曲放在榜单下部。这样每个入口只有一个主动作，平台切换也不再同时代表“浏览哪个平台”和“用什么播放”。

四条会贯穿全套界面的规则

浏览来源不是播放来源

榜单和歌单顶部的平台选择只决定内容从哪里读；播放仍按设置里的聚合策略自动选源。页面上用“榜单来源”“歌单来源”说清楚，播放器里再显示“当前播放源”。

本地先行，远程只是副本

新建、改名、加歌、删歌先落本机 Room，界面立刻反馈；同步在后台完成。断网时仍是完整可用的音乐库，而不是一个空壳。

内容页只做一套

平台歌单、排行榜、专辑和自建歌单共用同一套歌曲列表与批量操作。换源、收藏、下载、加入歌单的位置一致，不为每种来源复制一遍页面。

失败必须给出下一步

榜单单平台失败时提示换来源；同步冲突时给出保留哪一版；更新签名不一致时说明无法覆盖安装。所有错误都避免只说“失败”。

先知道发生了什么，
再决定听什么。

榜单页只做发现。内容平台只影响“榜单从哪里读”，不决定最终播放平台。榜单详情与歌单详情共用一条媒体列表，播放时仍使用全局聚合策略。

关键交互

  • 切换来源顶部胶囊只切换榜单内容来源；页面标注“榜单来源”，避免与播放源混淆。
  • 打开榜单点主榜或榜单行进入统一详情；榜单详情支持“播放全部”和“换源设置”。
  • 单曲操作点击曲目进入审计面板：可选音源、查看其他版本、合并或拆分，不把纠错按钮塞满列表。
  • 失败降级该来源取不到榜单时保留页面骨架，显示“换一个来源或稍后重试”，不展示空板块。
实现落点

复用 topLists 和 topListSongs。榜单列表按来源缓存 10 分钟；进入详情时再取歌曲。它们共用现有 canonical queue，播放地址只在真正播放时解析。

推荐和分类，
本来就属于同一件事。

原先散落在首页的推荐歌单、歌单分类和平台推荐，合并成一个可以持续浏览的歌单入口。平台选择是“歌单来源”，分类展开后不会跳走，也不会丢掉当前页。

关键交互

  • 推荐 / 分类用顶部段控件切换；分类页保留平台与页码，返回时恢复原位置。
  • 打开歌单平台歌单进入统一详情，可播放全部、收藏整张歌单或逐首换源。
  • 不支持分类平台没有分类能力时直接隐藏分类入口，不用空状态占据页面。
  • 不做假聚合不同平台的同名歌单不合并内容，只在搜索结果里作为来源并列显示。
实现落点

复用 recommendedPlaylists、categories 和 categoryPlaylists。平台与分页状态从 ViewModel 提升为独立浏览状态；推荐缓存 10 分钟，分类列表按“平台 + 分类 + 页码”缓存。

搜索框先接住问题，
再把音源摊开。

没有输入时，搜索页是历史和范围说明，不是一块空表格。聚合结果只出现一条主结果卡；各平台差异进入音源面板，不让列表在四种按钮之间打结。

关键交互

  • 提交才搜索输入过程不发请求；键盘搜索键或按钮才触发，避免频繁打到上游平台。
  • 自动识别链接粘贴支持的平台链接时直接显示“打开链接”，不再单独放一个“链接”分类。
  • 选择音源点结果打开底部面板，展示完整、试听、VIP、待检测；可记住这个选择。
  • 保留状态切去“我的”再回来，查询、滚动位置和结果都还在；不做无意义的重新搜索。
实现落点

继续使用 AggregateSearchEngine 的流式结果。新增搜索历史存储（DataStore，最多 20 条）、链接正则识别和统一的 SourcePickerSheet。人工合并 / 拆分放入曲目更多菜单。

音乐库先属于本机，
再同步到云端。

“我的”不是把旧音乐库改名，而是给自建歌单一个完整的工作台：本地修改立即生效，右上角云图标给出同步状态，冲突不会被自动覆盖。

关键交互

  • 歌单同步点顶部云图标或同步横幅打开同步中心；已连接、待同步、冲突三种状态在歌单行直接可见。
  • 本地优先新建、改名、加歌、删歌先写入 Room，之后才在后台同步；断网时界面不阻塞。
  • 冲突处理两个设备都修改同一歌单时，提供“合并两版 / 保留本机 / 使用云端”，默认推荐合并。
  • 只同步该同步的自建歌单和曲目元数据进入同步文件；Cookie、收藏、最近播放、下载文件不进入。
实现落点

新增 Room v4 的歌单条目表和同步账户表；用 WorkManager 执行后台同步；GitHub / Gitee 通过统一的 PlaylistSyncProvider 适配。令牌放 Android Keystore 加密存储，不写进 Room。

设置是索引，
不是一张滚动很长的表单。

主题、播放策略、账号、同步、存储和关于拆成独立子页。设置本身只负责把你带到正确的地方；每个改动即时保存，不需要“保存设置”按钮。

关键交互

  • 关于与更新版本号、构建号、更新检查、隐私说明、开源许可和项目主页集中在一个页面。
  • 手动与自动检查自动检查静默进行，只在“关于与更新”加一个圆点；手动检查才弹出结果。
  • 更新不打断播放下载在后台继续，进度保留；安装必须由你确认。
  • 账号隔离各平台 Cookie / 扫码登录在“平台账号”子页，不和播放策略混在一起。
实现落点

设置沿用 DataStore，但按领域拆分 key。新增 UpdateRepository 与 AboutScreen；更新清单由 CI 随 Release 发布，客户端只比较 versionCode。

页面设计 / 榜单

榜单只负责发现，
播放交给聚合层。

榜单是这次改版的新一级入口。平台排行榜本身不做跨平台合并，因为各平台的榜单口径不同，强行合成会产生一个没有意义的数字。跨平台只发生在“播放一首歌时重新找源”。

页面结构

榜单
├─ 顶部来源选择        网易云 / QQ / 酷狗…
├─ 主推榜单            趋势信息 + 前 3 首
├─ 更多榜单            该平台可用的榜单列表
├─ 平台热歌            当前来源的热门单曲
└─ 迷你播放器 + 五栏底导

进入榜单
├─ 封面、名称、更新频率、曲目数
├─ 播放全部 / 换源设置
└─ 排名列表

   └─ 更多：换源、其他版本、合并/拆分、收藏、下载

为什么这样分

原首页的“排行榜”只是推荐位；榜单作为主入口后，需要承载来源切换、榜单列表、热歌和详情页。与其把四种模块塞进首页，不如让榜单成为可反复浏览的空间。

不新增“综合热榜”。上游没有统一的加权公式，平台数据也不具备可比性。页面只展示真实的平台榜单；如果未来有可靠的数据源，再单独设计。

来源持久化

记住上次浏览的榜单来源，但默认仍使用设置中的默认平台；首次进入时与设置一致。切换来源只刷新本页，不改变播放设置。

交互与状态

场景界面行为实现注意
切换榜单来源顶部胶囊立即更新；主推榜单和列表显示骨架屏，失败时保留来源选择取消旧请求；用 generation 防止旧来源回包覆盖新来源

为什么不做成浮层

均衡器是多参数、需要反复试听的页面。把它塞进播放器浮层会遮挡封面，也不方便精细拖动。独立页面能容纳完整频段、预设和兼容性说明，并能在播放器继续播放的同时操作。

实时生效：没有“应用”按钮。预设和频段变化直接写入音频效果，页面只显示当前值；退出页面不会撤销。

按设备绘制：原型画的是常见五段（60 Hz / 230 Hz / 910 Hz / 3.6 kHz / 14 kHz）。实际界面按 Equalizer.getNumberOfBands() 与中心频率生成，不伪造固定频段。

保存与生效

DataStore 只保存 enabled、presetId 和自定义频段增益（dB）。应用启动或 PlaybackService 重建时读取并重新应用，不把设置写进歌曲或歌单。

预设曲线由应用定义：平直全 0 dB；流行强调低频与高频；摇滚提升低频和 3 kHz 附近；爵士轻微提升低频与高频；人声压低 60–230 Hz 并抬高中频。设备支持的频段数不同，就按中心频率做对数插值，而不是硬套五段。

不承诺所有耳机都生效。效果使用 Android 系统音频效果框架，受输出路由、OEM 音频实现和省电策略影响。界面要明确显示“当前输出是否生效”，不能把设置成功当成实际听到。

重点能力 / 音乐库同步

云端是副本，
本机才是主版本。

新增同步的目标只有一个：让用户自建的歌单可以在多台 Android 设备之间带走。实现上采用“本地数据库 + 单一版本化 JSON 快照 + 三方合并”，先支持 GitHub Gist 和 Gitee 代码片段，再扩展到其他后端。

V1 同步范围：仅自建歌单及其曲目元数据。不同步收藏、最近播放、下载文件、Cookie、播放地址、播放进度。这个边界既降低隐私风险，也避免把大文件和易失效 URL 写进 Gist。

稳定 ID

歌单使用 UUID，设备间不依赖自增主键。曲目使用 provider:id 作为稳定键。

删除用墓碑

删除歌单写入 deletedAt，同步一轮后再清理，避免另一台设备把删除项重新创建。

体积控制

只存元数据。单一文件超过 900 KB 时停止自动上传并提示导出，不在 Gist 中无界增长。

凭据与迁移

令牌使用 Android Keystore 的 AES-GCM 密钥加密，存入独立的 SecretStore，不进入 Room，也不进入同步 JSON。应用备份规则排除 SecretStore；断开同步时删除令牌和基线，但保留本机歌单。

现有 LocalPlaylist(id: Long, songs: JSON) 迁移到 UUID 歌单和逐条曲目表：开新表、解析旧 JSON、复制曲目和顺序、最后切换读取路径。迁移必须在事务中完成，旧表保留一个版本周期再删除。

私人 Gist 不是加密存储。它只是不出现在公开列表里。不要同步 Cookie、令牌或任何下载地址；同步文件只放歌单元数据。

自动同步的触发与克制

触发行为
歌单编辑标记 dirty，30 秒防抖后调度一次后台同步；5 分钟内不重复跑同一账户
App 回到前台若距上次同步超过 15 分钟且网络满足条件，静默拉取一次
手动“立即同步”忽略节流，显示显式进度和结果；失败弹 Snackbar，并给出重试
无网络 / 仅移动网络且开启 Wi-Fi 限制保持待同步，不弹错误；网络恢复后由 WorkManager 重试
令牌失效暂停自动同步，显示“需要重新登录”；本机编辑继续可用

新增能力 / 更新与关于

更新是一个校验流程，
不是一条下载链接。

应用内更新放在“关于与更新”：显示当前版本与构建号，自动检查静默进行，手动检查才展示结果。下载完成后必须校验哈希、包名、版本号和签名，再交给 Android 系统安装器，绝不静默安装。

检查与安装流程

检查

启动后最多每 24 小时一次，缓存 ETag；手动检查立即请求。

→
比较

只比较 versionCode，版本名仅用于展示。

→
下载

后台下载 APK，显示进度，可取消；只接受清单中的大小。

→
校验

SHA-256、包名、versionCode、签名证书逐项比对。

→
安装

FileProvider 打开系统安装器，用户确认覆盖安装。

自动检查不打扰

启动时如果发现稳定版更新，只在设置索引的“关于与更新”旁显示一个圆点，不弹窗。用户进入关于页才看到版本差异与更新说明。同一版本被“稍后”后，24 小时内不再提示。手动检查则无论是否有更新都给出明确结果。

只提供稳定通道。当前 main 发布稳定版，dev 为预发布；V1 不跟随预发布，避免用户被开发版打断。将来要加测试通道时，在清单里增加 channel 并由用户显式选择。

必须处理的失败

网络失败显示“检查更新失败”，提供重试和浏览器打开；不缓存错误结果
APK 哈希不符删除文件，提示“更新包校验失败”，不安装
包名不符视为错误清单，拒绝安装并记录诊断信息
版本号不高于当前视为服务端清单异常，提示已是最新版本
签名与当前安装不一致明确说明无法覆盖安装，建议从当前渠道重新下载；不能引导用户直接卸载而丢数据
未知来源权限未开启跳转到本应用的“安装未知应用”设置页；返回后保留已下载文件
存储空间不足在下载前检查清单大小，显示所需空间，不产生半截文件

Android 集成点

权限

REQUEST_INSTALL_PACKAGES 用于发起安装；Android 8+ 仍需用户在系统设置中允许“安装未知应用”。

文件共享

使用已有的 androidx.core 提供的 FileProvider，在 Manifest 中声明 cache/updates 路径。

包校验

用 PackageManager.getPackageArchiveInfo 读取 APK 的包名、versionCode、签名证书，与已安装应用比较；Android 6–8 使用旧签名 API 分支。

CI

在 Release job 中根据 output-metadata.json 生成 update.json 和 SHA-256，上传为 Release assets；只在成功完成测试后发布。

验收与边界

做到这些，

验收清单

  • 导航：底栏只有榜单、歌单、搜索、我的、设置五个主入口；首页内容没有丢失，分别落在榜单和歌单。
  • 来源：榜单 / 歌单页明确标注内容来源；播放源在播放器和音源面板中单独显示，两个概念不混用。
  • 搜索：提交才请求；切换页签后查询与结果保留；音源、试听、VIP、其他版本都能在两层内完成选择。
  • 音乐库：自建歌单可新建、改名、加歌、排序、删除；编辑先落本机，断网可用。
  • 同步：GitHub Gist 与 Gitee 至少各跑通一次创建、上传、拉取和冲突；令牌不以明文出现在数据库或日志。
  • 冲突：两个设备修改同一歌单时不会被静默覆盖；用户能选择合并、本机或云端，且操作前有本机备份。
  • 均衡器：开关、预设、自定义频段真实作用于当前播放；重建 audio session 或切歌后保持；不支持时明确显示“未生效”，不阻塞播放。触摸、键盘和遥控器都能调节频段。
  • 更新：能够检查版本、下载、校验 SHA-256 与签名、打开系统安装器；签名不一致时给出明确解释。
  • 关于：版本、构建号、许可、隐私说明、项目链接和诊断信息复制都可用。
  • 设备：手机上单手可完成主流程；平板和电视使用侧边导航；所有操作可仅用遥控器完成。

这次明确不做

综合热榜

没有可信的统一排名口径，不编造跨平台名次。只展示各平台真实榜单。

同步收藏和播放历史

V1 只同步自建歌单，避免把行为数据和个人偏好写进第三方 Gist。

把歌单写入第三方音乐平台

不调用各平台的写接口，不产生账号间数据不一致。自建歌单只存在于本机与用户选择的同步后端。

静默安装更新

Android 需要用户确认安装。应用负责下载和校验，系统安装器负责最后一步。

自动迁移不同平台的同名歌单

同名不代表同内容。只做并列展示，不做隐式合并。

云端中转服务
