方案五端界面区间选择状态实现规格

多选模式 · 交互与界面稿

给选择让位，
不给按钮让路。

把现在挤在两行里的操作条拆成选择控制和批量操作。歌曲仍然是画面的主体；逐首与区间不再靠猜，手机的迷你播放器和电视的遥控器焦点也各有明确去处。

5 类设备含折叠屏双姿态
8 个列表共用一套状态
48dp 起触摸与焦点目标
已选 4 首区间
播放下一首加入歌单取消收藏

一套状态，两种承载方式

不再让同一个 SelectionBar 靠 FlowRow 勉强适配所有宽度。断点决定操作放在哪里，数量、选择结果和动作顺序在所有设备上保持一致。

01 / 方案

单屏：顶部选择，贴底执行

手机竖屏和 800×360 横屏使用上下文顶栏；MiniPlayer 隐藏，底部统一变成满宽、贴底的操作导航。无播放时的悬浮导航也切换到这条贴底 Dock，列表底部自动让位。

双栏：左侧控制，右侧选歌

平板、折叠屏和电视把控制固定在左栏。右侧列表滚动时操作不动；电视从任一行按左方向键即可到达，无需先穿到底部。

有播放：隐藏 MiniPlayer，贴底导航换成操作

进入多选前是「迷你播放器 + 贴底导航」，进入后只保留同一条贴底导航，项目换成批量操作。

贴底 Dock

无播放：悬浮导航也换成贴底操作导航

不保留悬浮胶囊，也不加左右悬浮间距；与有播放时一样，只保留满宽贴底 Dock，并包含系统手势安全区。

贴底 Dock

多选期间只有一条贴底操作导航。退出多选、完成批量操作或返回手势结束后，再按进入前的有歌 / 无歌状态恢复迷你播放器、贴底导航或悬浮导航。

模式不再突然消失

从「多选」进入时可以是 0 首；取消最后一首也停留在多选，操作禁用。只有关闭、返回或批量操作成功才退出。

区间是一条明确的路径

第一次点起点，第二次点终点；两端带文字标记，结果按当前可见列表顺序选择。切换模式保留已选歌曲。

沿用当前组件，不另造皮肤

SongRow 仍为 64dp、48dp 封面、2dp 分段间距；连接式切换组、浮动工具栏、M3 色板和电视焦点环都来自现有实现。

五种设备，逐帧操作

默认是「喜欢」列表的区间选择。点设备里的歌曲、逐首/区间、全选和操作按钮都能看到状态变化；手机可先用「进入前底栏」切换有 MiniPlayer / 悬浮导航，再点设备里的「多选」查看整条底栏替换。

连续选择多段

完成一段后，再点一行成为新区间的起点；之前的选择不清空。回到「逐首」可单独取消任意一首，区间标记随锚点状态消失。

筛选、搜索与分组

区间只按当前可见且可选择的歌曲计算，跳过日期标题和「正在下载」等不可选行。筛选或搜索条件变化先退出多选，避免误带不可见歌曲。

空、满、撤销与危险操作

所有按钮的禁用和退出时机一致；破坏性操作按页面语义处理，不把「取消收藏」和「删除文件」混成同一个红色按钮。

落地规格

范围覆盖目前已使用多选的喜欢、最近播放、下载、自建歌单、本地音乐、聚合搜索、榜单和歌单/专辑详情，不重写业务操作。

05 / 实现
部件规格设备与行为
上下文顶栏64dp；关闭 48dp；标题 20sp；进入多选时替换原标题和返回键单屏固定顶部。双栏仍沿用 PageScaffold，但标题变为「已选 N 首 / 选择歌曲」
选择方式ConnectedToggleGroup：逐首 / 区间；每项至少 48dp 高切换保留 selected，清空 anchor；不截字，宽度不足时使用现有 WrapToggleGroup
全选未选 / 部分 / 全选三态图标；全选时文案为「全不选」只作用当前可见可选行；部分选择时再点 = 全选
歌曲行SongRow 64dp、封面 48dp、分段间距 2dp；选中 = secondaryContainer + 实心勾整行 Role.Checkbox；未选勾圈用 onSurfaceVariant，不提前染主色；起终点有文字标记
贴底操作导航沿用 ShortNavigationBar：满宽贴底、无悬浮圆角和左右间距；手机 72dp、横屏 64dp，另含系统导航安全区；图标 22dp + 12sp 标签，4 项等宽MiniPlayer 隐藏；有歌时把贴底导航项换成批量操作，无歌时 FloatingNavBar 也切成同一贴底 Dock；列表底部让位 88dp
左侧操作面板26–28dp 圆角；播放为 54dp 主按钮；下一首与加入歌单并列；上下文操作独立一行平板 340dp 左栏；电视 320dp；书本按折痕实际宽度收缩，不跨铰链
电视焦点沿用 tvFocusRing：3dp 主色描边、1.04 倍放大；焦点顺序与视觉顺序一致从歌曲行左键到操作面板；返回先退出多选，关闭后回到进入时的行或「多选」入口
动效与读屏顶栏与贴底导航内容交叉淡入；MiniPlayer 隐藏用快速退出动画；预测性返回沿用 selectionBackPreview减少动态效果时取消位移；区间完成播报「已选择第 3 至第 6 首，共 4 首」

动作顺序与页面文案

  • 固定顺序：播放 → 下一首 → 加入歌单 → 上下文操作；「下一首播放」在窄坞中简称「下一首」，读屏仍读完整含义。
  • 喜欢：取消收藏；最近播放：删除；下载：删除（先确认）；自建歌单：从歌单移除；本地音乐：上传。
  • 没有上下文操作的搜索、榜单、详情页只显示 3 项并等分宽度，不放空槽。
  • 播放、下一首、加入歌单和移除成功后统一退出多选；失败时保留选择，Snackbar 给出原因。

组件拆分与状态

  • 现有 Selection.kt 拆出 SelectionHeader、SelectionModeControl、SelectionActionDock、SelectionSidePanel；页面不再各自摆按钮。
  • SelectionState 暴露只读 anchor / rangeEnd 供标记和播报；0 首不再自动把 active 改为 false。
  • 单屏多选只保留贴底操作导航：MiniPlayer 不组合；有歌时沿用 ShortNavigationBar 容器，无歌时从 FloatingNavBar 切成同一贴底规格。退出时按 current 是否存在恢复原底栏；双栏和电视保留 BottomPlayerBar。
  • 窗口尺寸、折痕和导航继续读 Window.kt，不按设备名硬编码另一套断点。
360dp 竖屏与 800×360dp 横屏无按钮截字；多选期间只有一条满宽贴底操作导航，MiniPlayer 与普通导航项均不共存
1280×800dp 平板滚动右栏时，左侧操作保持可达
