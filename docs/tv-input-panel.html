这版视觉改了什么

减少层层卡片，让输入本身成为主角

大输入区，不再套小输入框

文字直接写在 30 dp 的作曲家表面上，去掉内部厚重描边。目标、内容和发送动作在一个视觉单元里完成。

设置是一组列表，不是四张营销卡

沿用应用里的 ListRow 与分组圆角，图标形状做区分。主页能快速扫到入口，但不会抢走输入的注意力。

宽屏重排，不是把手机拉长

横屏和平板左侧输入、右侧设置；子表单右侧放安全说明。折叠态把 72 px 中缝留给铰链。

实际响应式容器预览

状态与落地契约

手机负责填写，电视负责生效

设置表单和文字输入共用同一套会话与回执，不因为支持更多表单就放宽安全边界。

目标丢失只禁用当前输入框发送，四个设置入口和音乐搜索仍可用。
发送中锁定重复提交，保留草稿；切换场景会取消设计演示中的旧回执。
成功电视确认写入或保存后再报成功；文字写入成功才清空。
需要电视首次同步合并、证书确认等明确提示回大屏继续。
失败显示电视返回的具体原因，地址、账号与草稿原样保留。
过期断连停止提交，草稿留在本页；必须扫描电视上的新二维码。

沿用现有面板底座

  • LanPanelServer：128 位随机路径、局域网来源、10 分钟、同源 JSON、自定义写头。
  • 会话绑定：字段输入只写原目标；设置表单只开放明确列出的四种。
  • 敏感值：电视不回传已有令牌、密码或 Cookie；密码留空沿用由电视判断。
  • 验证：同步、WebDAV、音源与签名服务都调用原有业务入口，不在网页另写一套。

视觉与无障碍

  • 主题色继续由电视 SyncSetupTheme 注入，松绿只是兜底。
  • 触控目标至少 44 px，输入字号至少 16 px，焦点环与读屏标签完整。
  • 减少动态效果时关闭弹性形变、进度旋转和 Toast 弹入。
  • 不保存输入历史；切页不丢未提交草稿，过期不自动重放写操作。
