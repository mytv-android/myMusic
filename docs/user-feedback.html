总览：现在是怎样，改成怎样

「现在」一栏都是读代码得到的，括号里是出处。只有第 14 条是真 bug；第 15 条是电视上的可达性问题（按钮画着、遥控器到不了）；其余是功能缺口或交互不清楚。

#建议现在改成节
1Rush 加自定义配色配色只有 鲜艳 / 柔和 / 播放页。移植时把 Rush 的取色器换成了「播放页」，因为设置表只有数字、选项、开关三种控件（RushVisualizer.kt 文件头）。配色加第 4 项「自定义」，下面出两个色块（背景、文字），点开是自己画的取色面板：封面取色、色相/彩度/明度三条滑块、十六进制、对比度检查。设置表加一种 Color 控件。02
2Rush 的组合存成新风格预设每个模式只有一份设置（pluginSettings[modeId]），改了就覆盖。设置标题旁加「存为预设」和「随机搭配」。预设是一张独立的模式卡片，排在原模式后面，能选为固定、放进随机池、配给按速度的某一档。02

动画面板：三种换法各管各的，改完「保存并应用」

按理来说，如果选择了根据速度来检测的话，前面就不应该还是选择着某种特定的风格了，应该是前面都是灰色的……随机风格，除了现在的这个记忆，加一个可以选择在哪几个里面选随机；有以前播放的记录就优先用以前播放的那个，没播放过就从用户选择的样式组里面挑一个……好像没有立即生效，可以加一个保存偏好的按钮，退出返回到歌词页面时弹窗说检测到改动，是否保存并应用。

现在的面板是「卡片（单选）→ 每首歌换动画 → 这首歌固定用它 → 频谱 → 设置」。问题在于卡片在三种换法下都是单选：固定时它是全局选择，随机和按速度时点它的意思悄悄变成了「这首歌一直用它」，界面上看不出来。改法是把换法挪到最上面，让卡片的含义跟着换法变；「这首歌用哪个」单独成一行；面板里的改动先当草稿，保存时一次生效。

为什么改了看上去没生效

操作现在的行为（LyricDirector.kt）用户看到的
换法从固定改成随机这首歌在记忆里有结果就用记忆里的，没有才抽；抽到后要等两句之间空当 ≥1.5 秒、离下一句 ≥0.8 秒才换（canSwitchAt）点了「随机」，画面不动；歌词密的歌整首都等不到空当，留到下一首
换法改成按速度播到第 4 秒后才开始测，节拍网格置信度到 0.5 才算测到；测到后同样等空当节拍弱的歌（慢歌、纯人声）可能一直测不出，一直不换
改按速度某一档的动画只影响「测到的速度落在这一档」的歌，同样等空当这首歌不在这一档时什么也不变
随机 / 按速度时点了一张卡片这首歌在本次运行里手动优先（不落盘），随机时顺便写进记忆以为改了全局选择，其实只改了这一首

所以「保存并应用」要做的不只是写设置：它会立刻按新设置重算这首歌，马上换，不等空当（用 0.4 秒淡入淡出，避免硬切）。按速度且这首歌还没测出速度时，「这首歌」那一行显示「正在听速度…」，测到后立刻换。自动换歌时的「等空当」规则不变，只有手动保存这一下跳过它。

三种换法下，卡片和「这首歌」各是什么意思

换法卡片「这首歌」一行设置区编辑哪个模式
固定单选，选中＝所有歌都用它（现状）「跟着上面的选择」；「单独指定…」给这首换一个并固定选中的那个
随机多选，选中的进随机池；标题「从这些里随机 · 6/12」，旁边「全选 / 清空」。至少留 1 个，只剩 1 个时提示「等于固定」「上次听时抽到的（已记住）」或「这次从池里抽到的」；「改…」默认是正在显示的那个；标题旁的下拉可以换成池里任意一个
按速度整块灰掉、不可点，不画选中描边和勾；四档在卡片上面，每档点开选一个（预设也在里面）「测得 92 拍/分 → 慢」或「正在听速度…」；「改…」同上
随机时用哪个，按这个顺序：① 这首歌被固定过（pins）→ 用固定的；② 记忆里有这首（lyric_memory，最近 2000 首）→ 用记住的，即使它已经不在池里（这是用户要的「有记忆优先」）；记住的是一个已删除的预设时跳过；③ 都没有 → 从池里抽，不和上一首重复，抽到的写进记忆。设置区底部加一行「忘掉记住的结果 · 已记住 386 首」，想让池子重新生效时点它。

平板、手机横屏、折叠屏、电视

面板内容各设备一样，变的是它出现的位置，以及舞台露不露在旁边。露在旁边时（平板、横屏、书本姿态、电视），草稿直接画在舞台上，左上角标「预览：… · 还没保存」；被挡住时（手机竖屏）靠设置区顶部的大预览。下面每台设备都能点，和上面手机互不影响。

02

Rush：自定义配色、景深强度、存成风格预设

能不能加一个自定义配色……rush 它不是可以生成很多种风格吗？可以把它保存为预设的新风格预设……rush 歌词的那个景深模糊，能不能设置一个模糊度的调节。

三件事都落在动画面板的设置区。设置区顶部加一张大预览（同 Rush 原版「自定义歌词」页顶上的预览），草稿改动先在这里看效果。设置表的控件从三种（数字、选项、开关）扩到五种：加 Color（色块按钮）和 Slider（滑块），其他模式以后也能用。

封面
配色、对齐、字号、景深滑块、背景都能点；配色选「自定义」后点色块，右边的取色面板会跟着改。

三项改动的细节

项交互实现
自定义配色配色：鲜艳 · 柔和 · 播放页 · 自定义。选自定义后出两个色块按钮：背景、文字。初值取当前封面的鲜艳色和它的文字色，所以切过去时画面不跳。LyricSetting.Color(key, label, default)，值存 #RRGGBB 进 pluginSettings；Color 项可声明 visibleWhen = colors == custom。rushPalette 加 custom 分支：底色、字色用设置值，波浪色＝两者掺 25%，流光两端照原式从底色拉开。自定义颜色不跟封面变，切歌不过渡。
景深强度「景深模糊」开关换成滑块：关 · 弱 · 中 · 强，四个刻度可以吸附，中间也能停。「中」等于现在的强度。LyricSetting.Slider(key, 0f..1.5f, default = 1f, ticks = 0/0.5/1/1.5)；模糊＝min(|Δ|·3·k, 10·k) dp，k 是滑块值，「强」是 1.5 倍（最多 15dp）。旧的开关值迁移：开 → 1，关 → 0；电视、低内存、Android 12 以下默认 0。RushBlur 缓存上限 80px，15dp 在 3x 屏上是 45px，不用改缓存。
风格预设设置标题旁「随机搭配」骰子：背景、律动样式、配色、对齐随机组合一套（字号、景深保留），满意就「存成新预设」，起名默认「Rush 1」。预设是一张独立卡片，排在 Rush 后面，带「预设」角标；长按卡片：重命名 / 用当前设置覆盖 / 删除。LyricStagePrefs.presets: List<StagePreset(id, base, name, settings)>，卡片 id 是 rush#k3f9。LyricVisualizers.byId 认 base#id：返回 base 模式，舞台的 ctx.settings 换成预设的设置。预设能选为固定、进随机池、配给按速度某一档、给某首歌固定。删预设时引用它的地方退回 base 模式。不只 Rush，有设置项的模式都能存预设。只存在本机。

平板和电视上

平板（以及手机横屏、书本姿态）的设置在侧边面板里，舞台就在旁边，所以不放大预览，改动直接画在舞台上。电视上取色面板去掉十六进制输入，全部用方向键。两帧和上面手机共用一份设置，哪边改都会同步。

长按歌词选句，做成分享卡片：Rush 的九种卡全搬过来

分享功能可以参考 rush：长按歌词可以选中，可以选中几条歌词，然后会出现一个分享的按钮，然后可以编辑分享的格式。这一部分参考 Rush 的 style 和现有全屏播放页的 style。……另外，Rush 的歌词模板都可以搞进来啊，为什么只有一种。

入口只放在全屏歌词页。各种动画模式的排版差别很大（星潮、跳一跳根本不是列表），所以长按任何模式都进同一个「选句」层：舞台压暗，上面铺一张按时间排的歌词列表，长按的那句先选上。分享页照 Rush 的分享页做：上面预览、下面选项、底部操作。卡片样式把 Rush 的九种 CardTheme 全部照搬（色块 Spotify、叠卡 Rushed、竖排 Vertical、对句 Couplet、封面 Album Art、流光 Hypnotic、引言 Quote、乱排 Messy、粗糙 Brat），排版尺寸照 Rush 源码的 px 值（卡片 720px 宽）；再加一种我们自己的「播放页」样式，照现在的全屏歌词。Rush 的选项也一起搬：配色、卡片圆角、21 种封面形状、全屏 9:16、换背景图、乱排重新打乱、随机一套。

歌单导出成 myMusic 文件，能导入洛雪的导出文件

许愿可以兼容落雪的歌单导出文件的导入……可以学着落雪，把本地的歌单导出为特定格式的文件，然后可以导入。现在我们的歌单好像只有同步功能，没有导出功能。

其实已经有导出：同步 › 备份 › 导出到文件。但它一次导出全部歌单、收藏和平台 Cookie（SyncCoordinator.export），是给自己换机用的，不能发给别人。这里补的是按歌单导出、不带 Cookie的 myMusic 歌单文件，发给另一台装了 myMusic 的设备导入；导入沿用「我的 › 新建 › 从文件导入」这个入口，自动认格式：myMusic 歌单文件、同步备份，以及洛雪的 .lxmc / .json。

导入兼容洛雪，导出只出 myMusic：按开发者的决定，能导入洛雪导出的歌单文件；导出只出 myMusic 歌单文件，不导出洛雪 .lxmc，也不导出纯文本。

导出：myMusic 歌单文件

项做法说明
文件<歌单名>.mymusic.json（多选导出时 myMusic 歌单 N 个.mymusic.json），明文 JSON：{type:"mymusic.playlists", version:1, playlists:[…]}歌曲条目和同步文件里的一样（平台、id、extra、本地歌的线索），所有平台都能完整还原。只有这一种格式，面板上不出格式选择。
不带的平台账号、Cookie、收藏、设置、封面图片可以放心发给别人。换机整体迁移还是用同步 › 备份。
绑定歌单照常导出歌曲；绑定关系只记平台和歌单 id 作参考导入后是普通自建歌单，不自动绑定。

导入：认哪些文件

  • 认文件：按内容认，不管扩展名：文件头 1f 8b 先 gzip 解压；JSON 里 type 是 mymusic.playlists 走歌单导入预览，是洛雪的类型（见下）走洛雪导入预览；现有同步备份照旧走原来的恢复流程；都不是就提示「认不出这个文件」。
  • 本地歌：按文件线索（路径、大小）和歌名＋歌手在这台设备的本地音乐里找，找不到的跳过，预览里标出。

洛雪文件怎么读（取自 lx-music-desktop @ 323e4ba、lx-music-mobile @ 0669d1b 的源码）

洛雪 source歌曲字段对应本应用备注
wymeta.songId（数字）网易云 id
txmeta.songId＝songmid；strMediaMid、albumMid、meta.id（数字 id）QQ 音乐 id＝mid，其余进 extra
kgmeta.songId＝audio_id；meta.hash；meta.albumAudioId酷狗 id＝hash，extra.audio_id / album_audio_id洛雪的歌曲 id 没有 kg_ 前缀，是 audio_id_hash
kwmeta.songId＝rid（去掉 MUSIC_）酷我 id
mgmeta.songId、meta.copyrightId咪咕：用 copyrightId 换 content_id现有咪咕取流本来就会带 extra.copyright_id
localmeta.filePath、meta.ext按歌名＋歌手在本地音乐库里找找不到就跳过，预览里标出
  • 容器：洛雪写文件一律 gzip（文件头 1f 8b），读文件时按扩展名决定要不要解压。我们按文件头判断，不管扩展名；解出来是字符串时再解析一次（洛雪 1.14.0 有把导出序列化两次的问题）。
  • 类型：认 playListPart_v2（单个歌单）、playList_v2（全部歌单）、allData_v2（完整备份，取 playList），以及旧版 playListPart / playList / allData / defautlList（洛雪自己的拼写）。旧版歌曲字段是 songmid、img、types，照洛雪的 toNewMusicInfo 转成新版再处理。
  • 固定歌单：default（试听列表）、love（我的收藏）、temp（临时，跳过）按 id 认，不按名字（桌面版写的名字是 i18n 键 list__name_default）。
  • 去重：同一歌单里同平台同 id 只留一首；和本机同名歌单「合并」时按现有歌单合并规则（同一首不重复加）。导入的歌单是普通自建歌单，不绑定平台歌单，即使洛雪那边记了 sourceListId。

手机横屏全屏歌词是空白：bug，和机型关系不大

虽然不怎么用吧，但是可能可以做一下这个适配：手机横屏的全屏模式歌词好像用不了，不知道是不是手机型号的问题。

截图里横屏全屏歌词只有左侧控制栏和「Bang! · AJR」标题，歌词区一行都没有。读代码能完整复现原因，不是机型问题，只是在高度刚好不到 320dp 的手机上才会出现，所以看起来像机型相关。

原因

  1. PlayerScreen.kt:137：宽 ≥600dp 且宽 > 高就走 WidePlayer。手机横过来是 800dp 左右宽，所以横屏手机用的是平板的宽布局。
  2. LyricStage.kt:95：tooShort = maxHeight < 320.dp，量的是整个舞台（整窗）高度；LyricStage.kt:98–101：太矮就 classic?.invoke(…) 后返回。
  3. WidePlayer.kt:284：这里调用 LyricStage 时没传 classic（竖屏 PhonePlayer.kt:610 和桌面姿态 TabletopPlayer.kt:250 都传了）。而 WidePlayer.kt:245 在选了非经典模式时会把原来的歌词列表撤掉。两边都不画。
  4. 算一下：2400×1080 的手机按 480dpi 是 800×360dp，扣状态栏 24dp 剩 336dp，再扣横屏手势条约 16–24dp，就是 312–320dp，正好在 320 线下。显示大小调大一档的手机也会落到线下；420dpi 的同分辨率手机有 ~370dp，不出问题。仓库里的 WideStageLayoutTest 就用的 800×336。
  5. 选「经典」时不走这条路，所以经典模式横屏是好的；其他 9 种全空。平板上同一个缺口也会让「纯文本歌词」「没有歌词」时变空白。电视 TvPlayer.kt:245 同样没传。

修法

  • 补兜底：WidePlayer、TvPlayer 调 LyricStage 时传 classic = { LyricsList(…, sizing = LyricsSizing.TabletFocus) }，stageSafePadding 已经会把它摆进歌词栏。
  • 门槛按文字区算：tooShort 改成 maxHeight − insets.top − insets.bottom < 160.dp（文字区，不是整窗）。横屏手机文字区约 222dp，能放动画。个别需要高度的模式（跳一跳、巨幕）在 LyricVisualizer 上声明 minTextHeight，不够就照样退回经典。
  • 测试：WideStageLayoutTest 加 800×312 用例；LyricStage 加「太矮时一定有兜底」的单测。
  • 其他设备：平板和书本姿态高度够，平时不触发；但同一个缺口在「纯文本歌词」「没有歌词」时也会让 WidePlayer 空白，补兜底后一起好。电视 540dp 高不会太矮，同样只在没有逐行歌词时受影响。桌面姿态（TabletopPlayer）本来就传了兜底，不用改。
