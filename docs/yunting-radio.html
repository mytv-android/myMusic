把云听的电台
当作歌单

radio.cn（云听）的网页版接口不需要登录就能拿到全国 893 个广播电台：直播是 HLS 流，央广 19 个台还能取到当天完整的节目单回听，节目是可直接拖动的 m4a。 这意味着电台能直接套进现有歌单模型——一个电台一个歌单，直播是置顶曲目，回听节目是歌单里的歌，播放、队列、收藏、小组件都不用另造一套。

接口：ytmsout.radio.cn 无需登录 已实测 893 个电台 直播 HLS · 回听 m4a
00

结论

接口是云听网页版自己用的那套签名接口，参数和签名方式都写在页面 JS 里，没有用户态、没有鉴权头、没有设备指纹。能做，而且不用改动现有歌单页的交互。

893个电台19 个央广 + 31 个省级地区
19个台可回听央广系列，当天节目单 m4a
10个类型筛选新闻 / 财经 / 交通 / 音乐…
0处需要登录列表、直播、回听都不要 cookie
一句话形态：云听作为第 13 个 provider 接进来，歌单页顶部多一个「云听」平台；推荐页是热门电台，分类页是「类型 / 地区」两行筛选；点开一个电台就是歌单页，第一条是「直播 · 正在播出」，下面是今天的节目单。

02

接口：已实测的部分

四个 GET 接口撑起全部功能，域名 ytmsout.radio.cn。签名放在 header 里：把 query 参数按 key 排序拼成 k=v&k=v，再接 &timestamp=<毫秒>&key=<网页 JS 里的常量>，取大写 MD5。

用途路径参数返回
类型/web/appCategory/list/all任意占位参数（无参会被网关拦）10 个类型：全部 / 热门 / 新闻 / 财经 / 生活 / 交通 / 综艺 / 音乐 / 故事 / 民族
地区/web/appProvince/list/all同上32 项：国家 + 31 个省级地区（含新疆兵团）
电台列表/web/appBroadcast/listcategoryId、provinceCode，两个维度可组合电台数组，单次最多 74 条（山东全省）
可回听电台/web/appBroadcast/listenbackListprovinceCode=''（空串才是全国）19 个央广台；省级传编码返回空
节目单/web/appProgram/listByDatedate=YYYY-MM-DD、broadcastId当天节目：名称、起止时间、回听地址、封面
 
// 签名示例（Kotlin 侧照抄即可，key 就是网页 js/api.js 里的常量）
val sorted = params.toSortedMap().entries.joinToString("&") { "${it.key}=${it.value}" }
val sign = md5("$sorted&timestamp=$ts&key=$KEY").uppercase()

headers += mapOf(
  "Content-Type" to "application/json",
  "equipmentId"  to "0000",
  "platformCode" to "WEB",
  "timestamp"    to ts.toString(),
  "sign"         to sign,
)

直播：带签名的 HLS

每个电台返回四条流地址，playUrlMulti / mp3PlayUrlHigh 是同一路 192k 左右立体声（10 秒 ≈ 258 KB），playUrlLow 是低码率。地址里带 key 与 time：time 是签发时刻的十六进制秒值，每次请求列表都会重新签一份，所以播放前必须重取，不能把地址长期存进队列。

回听：30 分钟到 2.5 小时的整段 m4a

节目地址没有 token，可以直接拖动 seek，单集 20–180 MB（30 分钟约 43 MB）。以今天（11-05）的中国之声为例，节目单 23 条：06:30 新闻和报纸摘要、07:00 新闻纵横（2 小时）、09:30 新闻进行时（2.5 小时）、19:00 新闻有观点……

https://ytrecordbroadcast.radio.cn/echo/2/2963630829427583833.m4a?e=0&ps=1&r=1
Content-Type: audio/x-m4a   Content-Length: 43642466   → 30 分钟
没有单台详情接口。猜过的 /web/appBroadcast/detail、/get、/info 全部 404，所以「播放前换新 token」只能回到列表接口按 categoryId + provinceCode 拉一次再挑出 contentId——列表最多 74 条，代价可以接受。
03

形态：电台即歌单

不新增页面类型。云听复用 PlaylistsScreen 的平台 chip、分类筛选、歌单卡片和 PlaylistDetail，只把数据换掉。

歌单页 · 云听平台 chip 多一个「云听」，推荐 = 热门电台
类型 / 地区筛选两组 chips，选一个维度后按电台过滤
电台卡片 → 歌单页封面是台标，标题是台名，副标题是「正在直播：……」
直播 + 今日节目单第一条置顶「直播」，其余是今天的回听节目

数据映射

云听myMusic 模型字段
电台Playlistid=contentId，name=title，cover=image，description=subtitle（无节目单时留空），source="yunting"，link="https://www.radio.cn/pc-portal/erji/radioStation.html?id=639"

类型 / 地区PlaylistCategorygroup="类型" | "地区"，id="c{categoryId}" / "p{provinceCode}"

Provider 实现（data/native/YuntingProvider.kt）

方法行为
categories()类型 + 地区各拉一次 list/all，合成 PlaylistCategory 列表（地区排在类型后面）
recommendedPlaylists()appBroadcast/list {0,0} 取前 18 个央广台
categoryPlaylists(id)解析 c… / p…，另一个维度填 0，返回电台卡
playlistSongs(id)置顶直播 + 若在 19 个央广台里则拉 listByDate 拼今天节目；地区台只有直播一条
playableStream()直播项：按 extra["province"] 重拉列表换新 playUrlMulti；回听项直接返回原地址
parsePlaylist(link)认 radioStation.html?id=…，回到列表里找到该台
其余搜索 / 歌词 / 下载 / 登录 / 专辑 / 歌手 / 榜单全部不开，ProviderInfo 对应开关保持 false
为什么不做「每个节目一个歌单」：回听节目是整段广播，不是单曲，硬拆会得到几百个只有一条的"歌单"。以电台为歌单、节目为曲目，正好对应收听动作：先选台，再选今天听哪一段。
04

界面稿

组件全部沿用现有实现：平台 chip、推荐/分类分段、歌单大卡与三列网格、歌单详情的封面 + 播放全部/收藏、曲目行、迷你播放条、播放器。云听只带两处文案和一个状态：副标题写「正在直播：…」，以及直播曲目没有进度。

直播态只改三处：① 进度条不可拖动、时间文案改成「直播中 / 已播 mm:ss」；② MediaSession 不推送进度（回听曲目照旧）；③ 队列里的直播项 duration=0，不计入总时长。其余（后台播放、音质标签、睡眠定时、小组件）都不动。

风险与边界

  • 地址有时效：直播 token 是签发时刻生成的，队列里放久了会失效；playableStream() 播前重取一次即可，失败再回退。
  • 明文 HTTP：返回的流地址是 http://，仓库已开 usesCleartextTraffic；实测把 scheme 换成 https 也能拿到 200。
  • 回听只有央广：31 个地区传 provinceCode 回听列表都是空，地区台只有直播一条。
  • 节目不是单曲：一段 30–150 分钟，标题是节目名；队列里连播会接着放下一段节目，符合广播收听习惯。
  • 没有搜索、歌词、下载：ProviderInfo 全部关闭；后续如果要找台，用「地区 + 类型」两步筛选足够。
  • 不做的事：云听的听书/音频专辑接口（appAlbum）、账号与会员、节目往期（pageByColumn）——都留作后续，不进这一版。
